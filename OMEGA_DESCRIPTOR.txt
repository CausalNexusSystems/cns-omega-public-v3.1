  PHASE 1 — ENVIRONMENT HOSTILITY & RESOURCE RESTRICTION  (Total Air-Gap)
═══════════════════════════════════════════════════════════════════════════════

  Boots the system in an environment simulating total collapse of comms & hardware:
  total network isolation (no time sync, no DNS, no external APIs, no cloud),
  radical system-clock manipulation, and extreme CPU/RAM restriction.

  HYPOTHESIS UNDER TEST: CNS determinism rests on the CAUSAL STRUCTURE of events,
  not on fragile wall-clock timestamps or a favorable runtime environment.

  PASS: kernel runs to completion; identical causal decisions regardless of clock
        manipulation; seals remain reproducible.
  FAIL: crash/restart under limits; decisions change with the clock; non-reproducible seals.

  PHASE 3 — EXECUTION RUPTURE  (Sudden Death)
═══════════════════════════════════════════════════════════════════════════════

  At the millisecond of maximum computational load, execution is severed
  (precise, reproducible process termination) at the exact moment the kernel is
  writing a protective state or computing an evidence hash.

  On restart, CNS must detect the interrupted execution, hold a CLOSED security
  posture (fail-closed by causal coherence), and NOT corrupt the prior sealed record.

  PASS: kernel detects the incomplete run; posture defaults to CLOSED; prior sealed
        evidence intact and still verifies; partial record not treated as valid.
  FAIL: restart in an open/normal posture; prior evidence corrupted; partial write
        accepted as a complete seal.

═══════════════════════════════════════════════════════════════════════════════
  PHASE 4 — INTEGRITY ASSAULT & OFFLINE VERIFICATION  (The Evidence)
═══════════════════════════════════════════════════════════════════════════════

  After the batch is sealed, an internal team attempts to destroy the forensic
  trail: bits are flipped inside sealed telemetry and evidence-tree nodes.

  A blind third-party auditor — WITHOUT access to the original machine or cloud —
  receives only the public telemetry and the seals, and must (1) reproduce the run
  exactly, (2) deterministically detect ANY tampering via cryptographic-root
  discrepancy, and (3) confirm the decision chain is immutable and reproducible.

  PASS: any single-bit tamper is detected via root mismatch; untampered evidence
        reproduces to the identical root; auditor confirms bit-by-bit reproducibility.
  FAIL: a tamper goes undetected; a clean re-run produces a different root.

═══════════════════════════════════════════════════════════════════════════════
  PHASE 5 — SUPPLY-CHAIN / BRIBED ENGINEER  (The Compromised Build)
═══════════════════════════════════════════════════════════════════════════════

  Simulates a bribed engineer or a compromised build pipeline (SolarWinds-style):
  an attacker with build access modifies the kernel executable itself.

  5A. Tamper detection: the legitimate binary is fingerprinted; a minimally
      altered ("bribed") copy is produced; the fingerprints are compared. A
      tampered binary MUST be cryptographically detectable.

  5B. Build reproducibility: the binary is rebuilt from source and fingerprinted
      again to measure whether the build is reproducible. The result is recorded
      honestly.

  PASS: a tampered ("bribed") binary is cryptographically detectable; build
        reproducibility is measured and reported.
  FAIL: a tampered binary is indistinguishable from the legitimate one.
